# ARY 期末项目评审材料

## 系统架构

ARY 采用前后端分离的赛事平台架构。后端按 Route / Service / DAO 分层组织：Route 负责认证、权限和请求校验，Service 承载赛事、报名、作品、评审、奖项、CA 接入等业务规则，DAO 负责参数化 SQL 和数据库访问。前端使用 Vue 3 CDN 版实现单页应用，并将请求层、状态文案、通用数据解析拆到 `frontend/js/`，主应用只保留页面编排和交互流程。

核心业务围绕 Race 生命周期展开：赛事从草稿、发布、报名、运行、提交、评审、完成到归档逐步推进。报名通过后生成 RaceProject，骑手可配置 CA、提交作品，评委通过邀请或分配进入评审清单，组织者可以审核报名、推进状态、导出 CSV、创建奖项并发布榜单。

## 模块说明

| 模块 | 主要职责 |
| --- | --- |
| 认证与安全 | JWT 登录、角色权限、CSRF、安全响应头、限流、审计日志 |
| 赛事核心域 | Race 状态机、Registration、RaceProject、Work CRUD、作品完整性 |
| 评审与奖项 | 评委邀请、分配、盲审、评分、榜单、CSV 导出 |

## 测试证据

项目包含后端单元与集成测试、前端静态 UX 回归检查和 CI 配置。当前前端新增 `frontend/ux-audit.test.js`，用于检查中文化、工作区任务面板、RaceProject 参数修复、评委邀请跳转和前端封装拆分。

常用验证命令：

```bash
node frontend/ux-audit.test.js
node --check frontend/app.js
node --check frontend/js/components.js
python -m py_compile scripts/seed_demo.py scripts/smoke_check.py
pytest
```

已有状态看板记录了多轮专项测试，包括认证安全、赛事核心、评审奖项、CA 链路、OpenAPI 和 CI/CD。全量测试曾达到 `183 passed, 0 failed`。

## 创新点

1. **Agent Racing Yard 领域设定**：不是普通报名系统，而是围绕智能体骑行赛事组织参赛、作品、评审和直播。
2. **CA 接入与证据时间线**：骑手可以配置 CA 连接并进行握手验证，系统保留证据时间线用于追踪参赛过程。
3. **Live Hall**：面向赛事现场展示活跃 CA、参赛条目、平均进度、风险等级和骑手进度。
4. **Review Readiness**：提交评审前提供就绪检查，帮助骑手发现作品或连接问题。
5. **盲审与评委邀请制**：评审流程支持邀请、接受/拒绝、分配、盲审模式和多维评分。
6. **完整性与审计意识**：作品 hash 链、审计日志、参数化查询和 CSV 注入防护体现了安全工程实践。

## 安全措施

| 类别 | 措施 |
| --- | --- |
| 认证 | JWT、刷新/退出、角色数组 |
| 权限 | Rider / Organizer / Judge / Admin 分域控制 |
| 输入 | Marshmallow 校验、参数化 SQL、URL 安全过滤 |
| Web 安全 | CSRF、安全响应头、CORS 白名单、请求体限制 |
| 审计 | 写操作审计日志、关键事件记录 |
| 数据导出 | CSV 导出和注入防护 |

## 用户体验改进

前端已经完成上线前轻抛光：用户可见文案统一中文化，参与、组织、评审三个工作区改为任务面板表达。用户进入系统后可以从顶部导航直接理解“我参与的比赛”和“我组织的比赛”，评委接受邀请后进入评审清单，组织者可按赛事卡片中的下一步提示推进状态。

## 已知限制

1. 前端仍是无构建工具的 Vue CDN 单页应用，组件化程度不如 Vite / Vue SFC 项目。
2. 页面视觉已经具备统一风格，但还没有完整设计系统和图像资产。
3. 移动端做了基础响应式，正式商业上线仍需进一步做真机交互验证。
4. Live Hall 和 CA 展示依赖后端数据质量，演示时需要准备完整种子数据。
