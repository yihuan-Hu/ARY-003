# ARY 期末演示脚本

本文用于期末答辩或助教验收。目标是让评审者不需要摸索页面，也能在 8 到 12 分钟内看完核心工程亮点。

## 准备步骤

1. 启动后端和前端。
2. 生成演示数据：

```bash
python scripts/seed_demo.py
```

3. 可选：运行冒烟检查。

```bash
python scripts/smoke_check.py
```

演示账号统一密码：`Demo1234`

| 账号 | 角色 | 用途 |
| --- | --- | --- |
| `admin_demo` | admin | 展示系统级账号和审计数据 |
| `organizer_demo` | organizer | 展示组织者审核、状态推进、奖项和导出 |
| `rider_demo` | rider | 展示报名、参赛项目、CA、作品提交 |
| `judge_demo` | judge | 展示评委邀请、评分表单和盲审 |

## 演示路线 A：骑手参赛流程

账号：`rider_demo`

1. 打开首页，说明“期末演示入口”提供参赛、组织、评审、直播四条路线。
2. 进入“赛事”，选择 `ARY 公开报名赛`，点击报名入口。
3. 进入“我参与的比赛”，展示任务概览、报名记录、参赛项目和评委任务分区。
4. 打开 `ARY 智能体决赛` 对应参赛项目，展示 CA 连接、证据时间线、作品、骑行助手和评审就绪检查。
5. 新建作品草稿或查看已提交作品，说明作品提交后进入评审与榜单流程。

体现的工程点：RaceProject 参数修复、骑手视角权限隔离、CA 接入、作品状态、中文化任务面板。

## 演示路线 B：组织者赛事管理流程

账号：`organizer_demo`

1. 进入“我组织的比赛”。
2. 展示“组织者任务面板”：待审核、可推进、数据导出。
3. 打开赛事卡片，展示当前状态和下一步动作提示。
4. 查看报名审核区，说明提交、通过、拒绝状态。
5. 展示 CSV 导出按钮和奖项创建区。

体现的工程点：Organizer 跨赛事隔离、状态机、审核流程、导出、奖项榜单。

## 演示路线 C：评委评分流程

账号：`judge_demo`

1. 进入“我参与的比赛”，查看评审任务入口。
2. 进入“评审清单”，展示待评分数量和评分状态。
3. 打开作品评分表单，填写技术实现、创新性、展示表达、完成度和评语。
4. 提交评分，说明后端会记录 `judging_records`，赛事完成后评分封存。

体现的工程点：评委邀请制、盲审、评分唯一性、评审封存触发器。

## 演示路线 D：公开展示流程

无需登录或使用任意账号。

1. 打开“作品”，选择赛事查看公开作品。
2. 打开“榜单”，选择 `ARY 智能体决赛` 查看奖项结果。
3. 打开“直播大厅”，展示活跃 CA、平均进度、风险等级和骑手进度。
4. 打开“骑手档案”，说明公开档案可从榜单或作品链路跳转。

体现的工程点：公开 API、榜单聚合、Live Hall、RiderProfile。

## 讲解顺序建议

1. 先讲整体架构：后端 Route / Service / DAO，前端 `api/constants/ux/components` 拆分。
2. 再讲业务闭环：赛事 → 报名 → RaceProject → 作品 → 评审 → 奖项 → 榜单。
3. 最后讲工程质量：权限、安全、审计、测试、质量门禁、演示脚本。

## 常见问题

| 问题 | 回答 |
| --- | --- |
| 为什么不是普通 CRUD？ | 项目包含赛事状态机、盲审、CA 接入、证据时间线、Live Hall、作品完整性和质量门禁。 |
| 为什么前端不用构建工具？ | 课程项目选择低依赖部署，使用 Vue CDN，但通过 `frontend/js/` 做轻量模块化和组件化。 |
| 怎么证明可以运行？ | 运行 `scripts/seed_demo.py` 生成数据，再运行 `scripts/smoke_check.py` 验证核心 API。 |
